# Signy — подпись ЭЦП НУЦ РК без NCALayer

Расширение Chrome (Manifest V3), которое подписывает документы ключами НУЦ РК на сайтах, рассчитанных на
NCALayer, **без установки NCALayer, без локального сервера и без добавления корневых сертификатов в систему**.
Сайты работают как раньше: они открывают `wss://127.0.0.1:13579` и отправляют команды NCALayer — Signy
перехватывает это соединение внутри страницы и отвечает в том же формате, что NCALayer 1.4.

## Установка

1. Откройте `chrome://extensions`, включите «Режим разработчика».
2. «Загрузить распакованное расширение» → выберите папку `extension/`.
3. Откройте сайт (например, egov.kz) и выполните вход/подпись как обычно — вместо окна NCALayer откроется окно
   Signy.

Signy сразу работает на `*.kz`, `localhost` и `127.0.0.1`. Для других доменов нажмите на значок Signy и выберите
«Разрешить Signy на этом сайте» (Chrome запросит доступ только к этому сайту).

## Как перехватывается «запуск» NCALayer

NCALayer — это Java-приложение, которое держит WebSocket-сервер на `127.0.0.1:13579` с собственным TLS-сертификатом
(поэтому при установке он добавляет свой корневой сертификат в систему). Отдельной схемы URL для запуска у него нет
(проверено по `Info.plist` и коду из NCALayer.dmg): сайт просто пытается подключиться к порту. Signy подменяет все
пути, которыми страница «ищет» NCALayer:

| Что делает сайт | Что делает Signy |
|---|---|
| `new WebSocket('wss://127.0.0.1:13579/')` (также `localhost`, `[::1]`, `ws://`) | `content/inject.js` в MAIN-мире страницы подменяет `WebSocket` виртуальным сокетом: приходит приветствие `{"result":{"version":"1.4"}}`, `--heartbeat--` возвращается эхом, команды уходят в расширение. Остальные WebSocket-соединения не затрагиваются. |
| `fetch('https://127.0.0.1:13579/…')` — проверка «запущен ли NCALayer» | подменённый `fetch` отвечает без сети |
| картинка/iframe/переход на `https://127.0.0.1:13579/…` | правило declarativeNetRequest перенаправляет на ресурс внутри расширения |
| `navigator.permissions.query({name:'loopback-network'})` | ответ `granted`, чтобы сайт не показывал «разрешите доступ к локальной сети» |

Ничего не слушает порт 13579, в системе ничего не устанавливается.

## Что происходит при подписи

Каждая интерактивная команда открывает окно Signy: в нём видно, **какой сайт** просит подпись, операцию и сами
данные (XML с отступами, текст, PDF можно открыть для просмотра; если сайт передал только хэш — это явно показано).
Пользователь выбирает файл ключа `.p12`, вводит пароль, выбирает сертификат (с назначением, сроком, проверкой
цепочки до НУЦ РК) и нажимает «Подписать». Сайт получает ответ в формате NCALayer; закрытие окна = «Отмена».

- Закрытый ключ расшифровывается только в окне расширения и после операции затирается; пароль не сохраняется.
- «Запомнить ключ» сохраняет в `chrome.storage.local` исходный **зашифрованный** файл `.p12` (пароль — нет).
- В сеть уходит только запрос метки времени на `tsp.pki.gov.kz`, когда сайт её требует, и в нём только хэш
  подписи.
- Сертификаты НУЦ РК для проверки цепочки встроены в расширение; системное хранилище не используется.

## Поддерживаемый API NCALayer 1.4

**`kz.gov.pki.knca.commonUtils`**: `getActiveTokens` (пусто), `getKeyInfo`, `signXml`, `signXmls`,
`createCMSSignatureFromBase64`, `createCAdESFromBase64`, `createCAdESFromBase64Hash`, `applyCAdEST`,
`showFileChooser` + `createCMSSignatureFromFile` / `createCAdESFromFile`, `changeLocale`.

**`kz.gov.pki.knca.basics`** (`PKIExtras.sign`): форматы `xml`, `cms`, `raw`; параметры `decode`, `encapsulate`,
`digested`, `tsaProfile`, `outputCert`, несколько документов в `data`, проверки `signerParams` (EKU, ИИН, БИН,
серийный номер, цепочка).

**`kz.gov.pki.knca.applet.Applet`** (устаревший модуль, в том числе запросы без поля `module`): `browseKeyStore`
(выбор файла ключа — сайт получает условный путь `signy-file:…/имя.p12`), `showFileChooser`, `signXml(хранилище,
путь, AUTH|SIGN|…, xml)` — подпись XML с ответом `{result, errorCode:"NONE", secondResult: alias}`. В NCALayer 1.4
этот модуль обслуживает только класс `Applet`; старые методы `MainApplet` (`getKeys`, `createCMSSignature`,
`signPlainData`, `getNotAfter` …) там уже недоступны и отвечают `NoSuchMethodException` — Signy отвечает так же.
`signXml` этого модуля в NCALayer умеет только RSA и ГОСТ 34.310-2004, поэтому ключи ГОСТ 2015 для него
недоступны (с объяснением в окне).

**Не поддерживается**: аппаратные токены (Kaztoken, eToken, JaCarta, ID-карта, AKey, облачное хранилище),
выпуск/импорт ключей (`PKIEssentials.generateCsr` / `importCertificate`, `Applet.genKeyPairAndGetPKCS10`,
`setX509CertToKeyStore` …) — на такие запросы возвращаются штатные коды ошибок NCALayer, хранилища не изменяются.

## Криптография

Всё на чистом JavaScript в `extension/lib`: ГОСТ 34.310-2004, ГОСТ 34.10-2015 (512), ГОСТ 34.311-95, Стрибог,
RSA, PKCS#12 (форматы Kalkan/BouncyCastle и OpenSSL 3), CMS/CAdES-T с меткой времени RFC 3161, XMLDSig
(оформление и сериализация как у Apache Santuario + JDK в Kalkan). Форматы подписей повторяют Kalkan
(порядок r/s, little-endian ключи, выбор хэша по алгоритму сертификата, атрибуты CMS).

## Проверка

```bash
npm test
```

Юнит-тесты: векторы RFC/ГОСТ, сверка с node:crypto и OpenSSL, C14N против libxml2, сериализация XML против JDK
Transformer, проверка RSA-XML штатным JDK XMLDSig.

```bash
node test/e2e/run.mjs
```

E2E в Chromium (Chrome for Testing из кэша Playwright): тестовый сайт говорит протоколом NCALayer, окно Signy
заполняется как пользователем, каждая возвращённая подпись проверяется независимо.

```bash
KALKAN_JARS=/путь/kalkancrypt-0.7.8.jar:/путь/kalkancrypt_xmldsig-osgi-0.5.1.jar node test/tools/kalkan-crosscheck.mjs
```

Перекрёстная проверка: подписи Signy (XML, CMS, raw, в том числе на публичных тестовых ключах НУЦ РК из
`test/fixtures/nca-test-keys`) проверяются оригинальным провайдером Kalkan из дистрибутива NCALayer в локальной JVM —
только проверка, без установки и без сети.

Тестовая PKI (`test/fixtures/test-pki`, пароль `Qwerty12`) создаётся `node tools/testpki.mjs`; чтобы расширение
принимало такие ключи на сайтах, добавьте `ca-*.pem` в настройках → «Дополнительные доверенные корневые
сертификаты».
